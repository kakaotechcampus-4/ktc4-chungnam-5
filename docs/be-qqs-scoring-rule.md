# Q/Q/S 한 끼 채점 규칙

> 상태: 초안 · 규칙 버전 `v3` · 담당: BE 김윤재
> 수치는 잠정값이며 팀 검토를 거쳐 확정한다.

## 1. 개요

식사를 확정(`POST /meals/{mealId}/confirm`)하면 한 끼 단위로 Quantity · Quality · Satiety 를 채점한다.
채점 결과는 응답의 다음 필드에 담긴다.

| 필드 | 내용 |
| --- | --- |
| `scores.quantity` · `scores.quality` · `scores.satiety` | 0–100 정수. 근거가 없으면 `null` |
| `nutrients[].target` | 끼니 목표치 (소수 1자리) |
| `nutrients[].state` | `SHORT` · `OK` · `OVER` |
| `evidence.stageRuleVersion` · `weightProfileVersion` | 규칙 버전 (`v3`) |

구현 위치는 다음과 같다.

| 파일 | 역할 |
| --- | --- |
| `services/evaluation/rule_engine.py` | 채점 계산 (순수 함수) |
| `services/evaluation/stage_profile.py` | 단계별 기준 수치 |
| `services/evaluation/__init__.py` | 입력 수집 · 저장 · 응답 조립 |

## 2. 채점 원칙

- 세 축은 각각 따로 채점하고 합산하지 않는다 (D9).
- 투약 단계별 차이는 가중치로 두지 않는다. 대신 **해당 단계에서 위험한 방향의 기준을 더 엄격하게** 적용한다.
- 공공 DB 에서 음식 일부의 영양소 값만 비어 있으면 그 값은 0 으로 더한다. 모든 음식에 값이 없는 영양소와 열량은 0 으로 채우지 않는다 (7절).
- 기준에서 벗어난 정도는 차이(%p)가 아니라 **비율**로 감점한다. 많이 벗어날수록 점수는 계속 낮아지지만 0점이 되지는 않는다. 2배와 3배가 같은 점수로 뭉개지지 않게 하기 위해서다.

## 3. Quantity

평소 한 끼 열량(`users.baseline_meal_kcal`) 대비 섭취 비율 r 로 채점한다.

- r 이 단계별 적정 구간 [하한, 상한] 안에 있으면 100점이다.
- 상한을 넘으면 `100 × (상한 ÷ r)^k`, 하한에 못 미치면 `100 × (r ÷ 하한)^k` 이다.
- 지수 k 는 부족 쪽과 초과 쪽에 따로 둔다. 기본값은 2 이고, 해당 단계에서 위험한 쪽은 4 다. k 가 클수록 엄격하다.
- 0점은 아무것도 먹지 않았을 때(r = 0)뿐이다.

| 구간 끝 대비 | k = 2 | k = 4 |
| --- | --- | --- |
| 1.2배 (또는 0.83배) | 69 | 48 |
| 1.5배 (또는 2/3) | 44 | 20 |
| 2배 (또는 절반) | 25 | 6 |
| 3배 (또는 1/3) | 11 | 1 |

예: 유지기(60–85%, k = 2)에 평소의 100% 를 먹으면 `(85 ÷ 100)² = 0.72` → 72점이다.

## 4. Quality

단백질 · 식이섬유 · 나트륨 세 항목의 충족도를 가중 평균한다. 끼니 목표는 하루 기준의 1/3 이다 (하루 세 끼 기준).

| 항목 | 충족도 | 가중치 |
| --- | --- | --- |
| 단백질 | 섭취량 ÷ 목표, 최대 1 | 0.5 |
| 식이섬유 | 섭취량 ÷ 목표, 최대 1 | 0.2 |
| 나트륨 | 한도 이하 1, 넘으면 `(한도 ÷ 섭취량)²` | 0.3 |

- 단백질을 가장 무겁게 둔다. 투약 중 근손실 방지가 핵심이기 때문이다. 목표를 넘겨도 감점하지 않는다.
- 나트륨은 한도의 1.5배에서 0.44, 2배에서 0.25, 3배에서 0.11 이다. 0 이 되지 않는다.
- 식이섬유는 공공 DB 에 값이 빈 음식이 많고 시작기에는 목표를 낮춰 두는 항목이라 가장 가볍게 둔다.
- 일부 음식만 값이 비어 있으면 그 값을 0 으로 더한다.
- 모든 음식에 값이 없는 식이섬유 · 나트륨은 항목에서 빼고, 남은 항목의 가중치 합으로 다시 나눈다. 예: 식이섬유가 없으면 단백질 0.5 · 나트륨 0.3 을 0.8 로 나눈다. 0 으로 채우면 식이섬유는 부당하게 깎이고, 나트륨은 한도 이하로 판정되어 만점을 받기 때문이다.
- 모든 음식에 단백질 값이 없으면 Quality 는 `null` 이다. 단백질은 빼고 매기지 않는다.

예: 70kg 유지기 사용자가 단백질 14g(목표 28g) · 식이섬유 4g(목표 8.3g) · 나트륨 500mg(한도 767mg)을 먹으면
`0.5 × 0.5 + 0.2 × 0.48 + 0.3 × 1 = 0.646` → 65점이다.

단백질 목표는 **식사 시점 체중 × 단계별 계수 ÷ 3** 이다.

## 5. Satiety

사용자가 입력한 식후 포만감(%)을 점수로 사용한다.

## 6. 단계별 기준

| | PRE_DOSE | INITIAL | TITRATION | MAINTENANCE | REDUCED |
| --- | --- | --- | --- | --- | --- |
| 주의할 위험 | 없음 | 섭취 부족 · 과식 시 구토 | 섭취 부족 | 영양 부족 | 식욕 회복 · 과식 |
| Quantity 적정 구간 | 85–105% | 70–100% | 60–90% | 60–85% | 65–90% |
| Quantity 지수 k (부족/초과) | 2/2 | **4**/2 | **4**/2 | 2/2 | 2/**4** |
| 단백질 (g/kg/일) | 0.91 | 1.2 | 1.2 | 1.2 | 1.2 |
| 식이섬유 (g/일) | 25 | **16.7** | 25 | 25 | 25 |
| 나트륨 한도 (mg/일) | 2300 | 2300 | 2300 | 2300 | 2300 |
| Quality 적정 구간 | 70–100 | **80**–100 | **80**–100 | **80**–100 | 70–100 |
| Satiety 적정 구간 | 60–85 | 60–**80** | 60–85 | **65–80** | **65**–85 |

굵은 값은 기본값보다 엄격하게 둔 기준이다.
Quality · Satiety 적정 구간은 화면 표시용이며, 현재 API 응답에는 포함되지 않는다.

## 7. 값이 없을 때의 처리

| 상황 | 처리 |
| --- | --- |
| 체중 기록이 없음 | Quality 는 `null` |
| 식사 시각 이전 체중이 없음 | 가장 최근 체중을 사용 |
| 일부 음식의 단백질 · 식이섬유 · 나트륨 값만 비어 있음 | 비어 있는 값을 0 으로 더한다 |
| 모든 음식의 식이섬유 · 나트륨 값이 비어 있음 | `current` · `state` 는 `null`, Quality 에서 그 항목을 제외하고 남은 가중치로 다시 나눈다 |
| 모든 음식의 단백질 값이 비어 있음 | `current` · `state` 는 `null`, Quality 는 `null` |
| 음식 중 하나라도 열량 값이 비어 있음 | Quantity 는 `null` |
| DB 에서 찾지 못했거나 g 으로 환산되지 않은 음식이 있음 | 나머지 음식으로 채점하고 `NUTRITION_NOT_MATCHED` 경고를 함께 반환 |

## 8. 근거

단계별 위험 방향은 아래 문헌을 따른다. 투약 단계별 점수 기준을 제시한 문헌은 없어서, 구간 수치 · 지수 k · Quality 가중치는 제품 기준으로 정했다.

| 문헌 | 반영 내용 |
| --- | --- |
| Mozaffarian D, et al. *Obesity* 2025 — GLP-1 영양 공동 권고 | 감량 중 단백질 1.2–1.6 g/kg/일, 섭취 열량 16–39% 감소(위약 대비), 시작기 · 증량기 부작용, 시작 초기 고섬유 음식 회피 |
| Friedrichsen M, et al. *Diabetes Obes Metab* 2021 | 세마글루타이드 2.4mg 섭취량 −35% (위약 대비) |
